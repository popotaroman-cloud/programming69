# ส่วนที่ 1: วิธีแปลง Lecture Note → .ipynb (Jupyter Notebook)

## ปัญหาเฉพาะของฟอร์แมตเอกสารเราที่ต้องจัดการก่อนแปลง

ตรวจสอบไฟล์จริงแล้วพบจุดที่ต้องระวัง 3 จุด:

1. **โค้ดมีเลขบรรทัดกำกับ ไม่ใช่ Python ที่รันได้ตรง ๆ** เช่น
   ```
   01  def calculate_area(width, height):
   02      return width * height
   ```
   ต้องตัด prefix รูปแบบ `เลข 2 หลัก + เว้นวรรค 2 ครั้ง` (regex: `^\d{2}  `) ออกจากทุกบรรทัดก่อนใส่ลง code cell มิฉะนั้น Python จะ syntax error ทันที (ตัวเลขนำหน้าไม่ใช่ syntax ที่ถูกต้อง)

2. **หัวข้อย่อย "ตัวอย่างที่" ใช้รูปแบบไม่ตรงกันระหว่างไฟล์** — ตรวจแล้วพบว่า agent แต่ละตัวตั้งชื่อไม่เหมือนกัน:
   - `lecture_note_basic.md` ใช้ `#### ตัวอย่างที่ 1.1`, `1.2`, `1.3` (เลขหัวข้อ.เลขตัวอย่าง)
   - `lecture_note_intermediate.md` ใช้ `#### ตัวอย่างที่ 1`, `2`, `3` (รีเซ็ตทุกหัวข้อ ไม่มีเลขหัวข้อนำหน้า)
   - `lecture_note_advanced.md` และ `lab_pseudocode_to_python.md` ยังไม่ได้ตรวจรูปแบบ (ต้องตรวจก่อนเขียน parser จริง)

   → **ต้องเขียน parser ที่รองรับทั้ง 2 รูปแบบ** (ใช้ regex ที่ยืดหยุ่น เช่น `^#### ตัวอย่างที่ [\d.]+`) หรือไล่ normalize หัวข้อให้เหมือนกันก่อนแปลง (แนะนำอย่างหลัง เพราะกันปัญหาระยะยาวได้มากกว่า)

3. **ตัวแปรอาจชนกันข้ามหัวข้อ** — ถ้ารวมทุก topic ไว้ใน notebook เดียวแล้วรันบนสุดลงล่าง (top-to-bottom) ตัวแปรชื่อเดียวกัน (เช่น `result`, `total`) จากหัวข้อต่างกันอาจทับกันโดยไม่ได้ตั้งใจ ต้องตรวจด้วยการรันจริงหลังแปลง (ดู Step 6 ด้านล่าง) ไม่ใช่แค่แปลงแล้วจบ

## เครื่องมือที่แนะนำ
ใช้ไลบรารี **`nbformat`** (ไลบรารีทางการของ Jupyter) เขียนสคริปต์แปลงเอง แทนการใช้ `jupytext` ตรง ๆ เพราะเอกสารของเรามีโครงสร้างเฉพาะตัว (trace table, คำอธิบายภาพรวม, เลขบรรทัด) ที่ไม่ตรงกับฟอร์แมตมาตรฐานที่ jupytext รู้จัก การเขียน parser เองควบคุมผลลัพธ์ได้แม่นยำกว่า

## ขั้นตอน

1. **เขียนสคริปต์ `scripts/md_to_ipynb.py`** รับไฟล์ `.md` 1 ไฟล์ แล้วแบ่งเนื้อหาด้วย regex ตามลำดับชั้น: `## หัวข้อที่ N` → `#### ตัวอย่างที่ ...` → บล็อกโค้ด/Output/trace table/คำอธิบายภาพรวม

2. **ต่อ 1 หัวข้อ (topic)** สร้าง:
   - 1 markdown cell: ชื่อหัวข้อ + ย่อหน้าแนวคิด (ก่อนตัวอย่างแรก)
   - ต่อ 1 ตัวอย่าง (repeat 3 ครั้ง): 1 markdown cell (หัวข้อย่อยของตัวอย่าง) + 1 code cell (โค้ดที่ตัดเลขบรรทัดออกแล้ว, ใส่ output ที่ verify ไว้แล้วเป็น pre-populated cell output ผ่าน `nbformat.v4.new_output(output_type='stream', text=...)`) + 1 markdown cell (ตารางการเปลี่ยนแปลงค่า + คำอธิบายภาพรวม — เก็บเป็น markdown table ตรง ๆ ได้เลย ไม่ต้องแปลงรูปแบบ)

3. **ส่วนแบบฝึกหัดท้ายบท**: แยกเป็น 2 notebook ต่อไฟล์ต้นทาง
   - `<ชื่อไฟล์>_student.ipynb` — มีแค่โจทย์ (markdown cell) + code cell ว่างให้นักเรียนกรอกเอง (สำหรับข้อ coding exercise) — **ไม่มีเฉลย**
   - `<ชื่อไฟล์>_answers.ipynb` — มีทั้งโจทย์และเฉลย (code cell มีคำตอบ + output จริงที่ verify ไว้แล้ว) สำหรับอาจารย์/เฉลยให้นักเรียนดูทีหลัง

4. **ไฟล์ lab (`lab_pseudocode_to_python.md`)** แปลงแบบเดียวกับแบบฝึกหัด: notebook นักเรียนมี pseudocode + code cell ว่าง, notebook เฉลยมีโค้ด Python เต็ม + output จริง

5. **Validate โครงสร้าง**: รัน `nbformat.validate(nb)` ทุกไฟล์ที่สร้าง เพื่อเช็คว่าไฟล์ `.ipynb` ไม่เสีย

6. **Execute จริงเพื่อจับปัญหาตัวแปรชนกัน**: รัน `jupyter nbconvert --to notebook --execute` กับทุก notebook (โดยเฉพาะไฟล์ `_answers.ipynb` ที่มีโค้ดครบ) ถ้ามี error (เช่น `NameError`, ผลลัพธ์ไม่ตรงกับที่บันทึกไว้ในเอกสารต้นฉบับ) แปลว่ามีตัวแปรชนกันข้ามตัวอย่าง/ข้ามหัวข้อ ต้องแก้ (เปลี่ยนชื่อตัวแปรให้ไม่ซ้ำ หรือแทรก markdown cell แนะนำให้ "Restart Kernel" ก่อนหัวข้อถัดไป)

7. **ตรวจว่า output ที่ execute ใหม่ตรงกับ output ที่บันทึกไว้ในเอกสารต้นฉบับทุกตัวอย่าง** (diff ผลลัพธ์) เพื่อยืนยันว่าไม่มี output ไหน "เพี้ยน" ไปจากตอนที่ agent verify ไว้ตอนเขียนเอกสาร

# ส่วนที่ 2: วิธีแปลง Lecture Note → สไลด์

## สิ่งที่ตรวจพบในโค้ดจริงของสไลด์ที่มีอยู่แล้ว (week_06_function/slides/)

ไฟล์ `slides/06_function.html` **ไม่มีตัว build script** — เป็น HTML/CSS/JS ไฟล์เดียวที่เขียน slide แต่ละแผ่นเป็น `<div class="slide">` ฝังตรงใน `<body>` (สร้างโดย agent ก่อนหน้าด้วยมือ ไม่ใช่ generator อัตโนมัติ) โครงสร้าง markup จริงต่อ 1 สไลด์:

```html
<div class="slide slide-N" data-title="ชื่อสไลด์">
  <div class="slide-header">
    <div class="slide-num">Slide N+1</div>
    <div class="slide-title">ชื่อสไลด์</div>
  </div>
  <div class="key-message">Key Message หนึ่งประโยค</div>
  <div class="slide-content">
    <div class="code-block"><div class="code-lang">python</div><pre><code>...โค้ด...</code></pre></div>
    <p><strong>Output:</strong></p>
    <div class="code-block"><pre><code>...ผลลัพธ์...</code></pre></div>
    <div class="placeholder">📊 <em>คำอธิบายไดอะแกรมที่ยังไม่ได้วาดจริง</em></div>
  </div>
</div>
```
และ `slides/index.html` มีเนื้อหาเหมือนกับ `06_function.html` เป๊ะ (507 บรรทัดเท่ากัน) — เป็นไฟล์ entry-point คู่กัน ต้องอัปเดตทั้งคู่พร้อมกันเสมอ

## ทำไมแปลงตรง ๆ 1:1 ไม่ได้
Lecture note หนาแน่นเกินกว่าจะใส่ในสไลด์ได้ทั้งหมด (เช่น หัวข้อ 1 หัวข้อมี 3 ตัวอย่าง + trace table + คำอธิบายภาพรวมยาว ๆ + 20 ข้อแบบฝึกหัด) สไลด์เดิมของสัปดาห์ 6 มีแค่ **7 สไลด์รวมทั้งหมด** เน้นความกระชับ ต้อง**คัดและย่อเนื้อหา** ก่อน ไม่ใช่แปลงทุกบรรทัด

## ขั้นตอน (2 ระยะ)

### ระยะ A: คัดและย่อเนื้อหา (lecture note → slide-source .md)
ทำทีละหัวข้อ (15 หัวข้อ):
1. เลือก**ตัวอย่างเดียว**ที่ชัดที่สุดจาก 3 ตัวอย่างในหัวข้อนั้น (ปกติคือ "ตัวอย่างที่ 1 (หลัก)") — ตัวอย่างอื่นทิ้งไปสำหรับสไลด์ (แต่ยังอยู่ใน lecture note เต็มสำหรับอ่านเพิ่มเติม)
2. ย่อย่อหน้าแนวคิดให้เหลือ **Key Message 1 ประโยค**
3. เก็บโค้ด + Output ตามเดิม (ตัดเลขบรรทัดออก เพราะสไลด์เดิมของสัปดาห์ 6 ไม่มีเลขบรรทัดกำกับ)
4. **ตัด trace table ออก** (แน่นเกินไปสำหรับสไลด์) แปลงเป็น `[FIGURE: ...]` placeholder แทน (ตามธรรมเนียมสไลด์เดิม) หรือย่อเป็น bullet 2-3 บรรทัด
5. ตัดคำอธิบายภาพรวมเหลือ bullet สั้น 1-2 ข้อ
6. **ไม่ใส่แบบฝึกหัด/เฉลยลงสไลด์โดยตรง** — อ้างอิงกลับไปที่ lecture note แทน (เช่น สไลด์สุดท้ายของแต่ละหัวข้อพูดว่า "แบบฝึกหัดเพิ่มเติมดูใน lecture note")
7. บันทึกผลลัพธ์เป็นไฟล์ slide-source ใหม่ (รูปแบบเดียวกับ `slides/06_function.md` เดิม คือ `## Slide N — ชื่อ` + `**Key Message**` + โค้ด + Output)

**คำถามสำคัญที่ต้องตัดสินใจก่อนเริ่ม**: หัวข้อ 6–15 (ระดับกลาง/สูง) เป็นเนื้อหา**นอกขอบเขตสอบ**ของสัปดาห์ 6 ตามที่ตกลงไว้ — ควรทำเป็น สไลด์ชุดเสริมแยกต่างหาก (เช่น `slides_extra/` หรือสัปดาห์ถัดไป) ไม่ควรผสมกับ `06_function.md` ที่เป็นสไลด์สอบจริง 7 แผ่นเดิม เพื่อไม่ให้ขอบเขตสอบเพี้ยนไปจากที่คุยกันไว้ก่อนหน้านี้

### ระยะ B: แปลง slide-source .md → HTML (รูปแบบเดียวกับที่มีอยู่)
1. คัดลอกส่วน `<style>` และ `<script>` ทั้งหมดจาก `06_function.html` เดิม (เป็น boilerplate ที่ไม่ต้องแก้ ใช้ร่วมกันได้กับทุกสัปดาห์อยู่แล้ว — ควร diff กับสัปดาห์อื่นเพื่อยืนยันว่าเหมือนกันจริงก่อนเชื่อว่า reuse ได้ 100%)
2. ต่อ 1 สไลด์ใน slide-source .md → generate `<div class="slide slide-N" data-title="...">...</div>` ตาม markup ที่ตรวจพบด้านบน (เลขสไลด์ต้อง sync กับ `data-title`, `slide-num`, และ progress bar ที่คำนวณจากจำนวนสไลด์ทั้งหมด — `style="width:14.3%"` ในตัวอย่างคือ 1/7 ดังนั้นถ้าจำนวนสไลด์เปลี่ยน ต้องคำนวณเปอร์เซ็นต์ใหม่)
3. ใส่ผลลัพธ์ทั้งหมดลง **ทั้ง `06_function.html` และ `index.html` พร้อมกัน** (สองไฟล์ต้องเหมือนกันเป๊ะเสมอ ตามที่พบว่าเป็นแบบนั้นอยู่แล้ว)
4. เปิดดูในเบราว์เซอร์จริงเพื่อตรวจว่า layout ไม่ล้น (โดยเฉพาะโค้ด/ตารางยาว ๆ ที่ถูกย่อมาจาก lecture note อาจยังยาวเกิน slide เดิม ต้องย่อเพิ่ม)
5. ถ้าต้องการวาด diagram จริงแทน placeholder — ใช้ matplotlib สร้างภาพแล้ว base64-encode ฝังใน `<img>` (CSS มี class `.slide-figure img` รองรับอยู่แล้ว ตามที่เห็นใน comment `/* Generated figure (matplotlib base64 PNG) */`)

## สรุปความแตกต่างสำคัญระหว่าง 2 การแปลง

| | → .ipynb | → สไลด์ |
|---|---|---|
| ระดับรายละเอียด | ครบเกือบเท่าต้นฉบับ (คัดแค่ format) | ต้องย่อหนักมาก (เลือก 1 ใน 3 ตัวอย่าง, ตัด trace table) |
| ตัวอย่าง/หัวข้อ | ใช้ทั้ง 3 | ใช้แค่ 1 |
| แบบฝึกหัด | แปลงครบ (แยกไฟล์ student/answers) | ไม่ใส่ลงสไลด์ อ้างอิงกลับไปเอกสารแทน |
| เครื่องมือ | สคริปต์ `nbformat` เขียนเอง | เขียน HTML ต่อจาก template เดิมที่มีอยู่ |
| ต้อง execute ยืนยันซ้ำ | ✅ (จับตัวแปรชนกัน) | ไม่จำเป็น (โค้ด/output คัดลอกมาจากที่ verify แล้ว ไม่เปลี่ยนแปลง) |
| ความเสี่ยงหลัก | ตัวแปรชื่อชนกันข้ามหัวข้อเมื่อรันในสมุดเดียว | เนื้อหาล้นกรอบสไลด์ที่ออกแบบไว้สำหรับความกระชับ |
