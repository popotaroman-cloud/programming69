## ระดับพื้นฐาน

### ข้อที่ 1 (Pseudocode)

**โจทย์**: ร้านสะดวกซื้อต้องการฟังก์ชันคำนวณเงินทอนให้ลูกค้า โดยรับจำนวนเงินที่ลูกค้าจ่าย (paid)
และราคาสินค้า (price) เป็นพารามิเตอร์ แล้วคืนค่าจำนวนเงินทอนกลับออกมา

**Pseudocode**:

```
FUNCTION calculate_change(paid, price)
    change = paid - price
    RETURN change
END FUNCTION

PRINT CALL calculate_change WITH (500, 350)
```

**โจทย์ให้แปลง**: จงแปลง pseudocode ข้างต้นเป็นโค้ด Python จริงด้วยตนเอง แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

## ระดับกลาง

### ข้อที่ 1 (Pseudocode)

**โจทย์**: บริษัทขนส่งต้องการฟังก์ชันคำนวณค่าจัดส่งสินค้า โดยรับน้ำหนักพัสดุ (weight) เป็นกิโลกรัม
และอัตราค่าจัดส่งต่อกิโลกรัม (rate) เป็นพารามิเตอร์ แต่ถ้าลูกค้าไม่ระบุอัตราค่าจัดส่งมา ให้ใช้อาร์กิวเมนต์ค่าเริ่มต้น
เป็น 20 บาทต่อกิโลกรัม

**Pseudocode**:

```
FUNCTION calculate_shipping_cost(weight, rate = 20)
    cost = weight * rate
    RETURN cost
END FUNCTION

PRINT CALL calculate_shipping_cost WITH (3)
PRINT CALL calculate_shipping_cost WITH (3, 25)
```

**โจทย์ให้แปลง**: จงแปลง pseudocode ข้างต้นเป็นโค้ด Python จริงด้วยตนเอง แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 2 (คำอธิบายขั้นตอน)

**โจทย์**: ต้องการฟังก์ชันหาผลรวมของจำนวนเต็มบวกตั้งแต่ 1 ถึง n โดยใช้เทคนิคการเรียกซ้ำ (recursion)

**คำอธิบายขั้นตอน**: ให้เขียนฟังก์ชันชื่อ `sum_up_to` ที่รับพารามิเตอร์หนึ่งตัวคือจำนวนเต็มบวก `n`
ฟังก์ชันนี้ต้องทำงานด้วยการเรียกซ้ำ (recursion) ไม่ใช่การวนลูป โดยมีขั้นตอนดังนี้ ถ้า `n` เท่ากับ 1 ให้คืนค่า 1
กลับไปทันที (นี่คือกรณีฐาน หรือ base case) ถ้า `n` มากกว่า 1 ให้คืนค่าผลลัพธ์ของ `n` บวกกับผลลัพธ์ที่ได้จากการเรียกฟังก์ชัน
ตัวเองซ้ำด้วยค่า `n - 1` จากนั้นให้ทดลองเรียกฟังก์ชันนี้ด้วยค่า `n` เท่ากับ 5 แล้วพิมพ์ผลลัพธ์ออกทางหน้าจอ

**โจทย์ให้เขียนโค้ด**: จงเขียนฟังก์ชัน Python จากคำอธิบายขั้นตอนข้างต้นด้วยตนเอง แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 3 (คำอธิบายขั้นตอน)

**โจทย์**: แอปรีวิวร้านอาหารต้องการฟังก์ชันหาค่าเฉลี่ยคะแนนรีวิวของร้าน โดยจำนวนรีวิวของแต่ละร้านไม่เท่ากัน
(บางร้านมี 3 รีวิว บางร้านมี 5 รีวิว)

**คำอธิบายขั้นตอน**: ให้เขียนฟังก์ชันชื่อ `average_rating` ที่ออกแบบให้รับอาร์กิวเมนต์จำนวนไม่จำกัด
(arbitrary arguments) แทนที่จะกำหนดจำนวนพารามิเตอร์ตายตัว โดยแต่ละอาร์กิวเมนต์ที่ส่งเข้ามาคือคะแนนรีวิวหนึ่งค่า (1–5 ดาว)
ขั้นตอนการทำงานคือ นำคะแนนรีวิวทั้งหมดที่ได้รับมาบวกกันเป็นผลรวม แล้วหารด้วยจำนวนค่าที่รับเข้ามาทั้งหมด
เพื่อคำนวณเป็นค่าเฉลี่ย แล้วคืนค่าเฉลี่ยนั้นกลับออกไป จากนั้นให้ทดลองเรียกฟังก์ชันนี้สองครั้ง ครั้งแรกด้วยคะแนน 5, 4, 5
(3 รีวิว) และครั้งที่สองด้วยคะแนน 3, 4, 2, 5, 4 (5 รีวิว) แล้วพิมพ์ผลลัพธ์แต่ละครั้งออกทางหน้าจอ

**โจทย์ให้เขียนโค้ด**: จงเขียนฟังก์ชัน Python จากคำอธิบายขั้นตอนข้างต้นด้วยตนเอง (ใช้ syntax อาร์กิวเมนต์จำนวนไม่จำกัดของ Python)
แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 4 (โจทย์/pain point เท่านั้น)

**โจทย์**: แอปเพลงเก็บรายชื่อเพลงในเพลย์ลิสต์ของผู้ใช้ไว้ในลิสต์ (list) หนึ่งตัวต่อผู้ใช้หนึ่งคน
เมื่อผู้ใช้กดปุ่ม "เพิ่มเพลงเข้าเพลย์ลิสต์" ระบบต้องการฟังก์ชันที่รับเพลย์ลิสต์เดิมกับชื่อเพลงใหม่เป็นพารามิเตอร์
แล้วเพิ่มเพลงชิ้นใหม่เข้าไปใน**เพลย์ลิสต์เดิมนั้นโดยตรง** (ไม่สร้างเพลย์ลิสต์ใหม่ขึ้นมาแทน) เพื่อให้ตัวแปรเพลย์ลิสต์เดิมที่อยู่นอกฟังก์ชัน
เห็นการเปลี่ยนแปลงด้วย

ให้ออกแบบและเขียนฟังก์ชัน Python ที่ทำงานตามที่กล่าวมา โดยไม่มี pseudocode หรือขั้นตอนกำกับ
ต้องอาศัยความเข้าใจเรื่องการส่งค่าแบบ by reference ของอ็อบเจกต์ที่เปลี่ยนแปลงค่าได้ (mutable) อย่าง list ในภาษา Python
(คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 1 (Pseudocode)

**โจทย์**: ฝ่ายบุคคลของบริษัทมีรายชื่อพนักงานเก็บเป็นชุดข้อมูล (แต่ละคนมีฟิลด์ `name` และ `years` คืออายุงานเป็นปี)
ต้องการเรียงลำดับพนักงานจากอายุงานน้อยไปมาก โดยใช้ฟังก์ชันนิรนาม (lambda) เป็น "key function" ระบุว่าจะเรียงลำดับตามฟิลด์ใด

**Pseudocode**:

```
SET employees TO [
    { name: "สมชาย", years: 5 },
    { name: "สมหญิง", years: 2 },
    { name: "วิชัย", years: 8 }
]

SET get_years TO LAMBDA (employee) RETURNS employee.years

SET sorted_employees TO SORT employees BY get_years IN ASCENDING ORDER

FOR EACH employee IN sorted_employees
    PRINT employee.name, employee.years
END FOR EACH
```

**โจทย์ให้แปลง**: จงแปลง pseudocode ข้างต้นเป็นโค้ด Python จริงด้วยตนเอง (เก็บพนักงานแต่ละคนเป็น dictionary และใช้ `lambda`
ร่วมกับฟังก์ชันเรียงลำดับของ Python) แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 2 (คำอธิบายขั้นตอน)

**โจทย์**: แอปออกกำลังกายต้องการระบบคำนวณแคลอรี่ที่เผาผลาญแบบยืดหยุ่น สามารถสลับเปลี่ยนสูตรคำนวณตามความหนักของการออกกำลังกาย
ได้โดยไม่ต้องแก้โค้ดฟังก์ชันหลัก

**คำอธิบายขั้นตอน**: ให้เขียนฟังก์ชันอันดับสูง (higher-order function) ชื่อ `apply_workout_intensity` ที่รับพารามิเตอร์สองตัวคือ
ระยะเวลาออกกำลังกายเป็นนาที (`duration`) และฟังก์ชันคำนวณแคลอรี่ (`intensity_function`) โดยพารามิเตอร์ตัวที่สองนี้ต้องเป็นฟังก์ชันที่ถูกส่งเข้ามาเป็นค่า
(ตามแนวคิดฟังก์ชันชั้นหนึ่ง หรือ first-class function) ขั้นตอนการทำงานของ `apply_workout_intensity` คือ เรียกใช้ `intensity_function`
โดยส่งระยะเวลาเข้าไป แล้วคืนค่าผลลัพธ์ที่ได้กลับออกไปตรง ๆ

จากนั้นให้เขียนฟังก์ชันย่อยสองฟังก์ชันแยกต่างหาก ฟังก์ชันแรกชื่อ `light_workout` รับระยะเวลาหนึ่งค่า
แล้วคืนค่าแคลอรี่ที่เผาผลาญโดยคูณด้วย 5 ฟังก์ชันที่สองชื่อ `intense_workout` รับระยะเวลาหนึ่งค่า แล้วคืนค่าแคลอรี่ที่เผาผลาญโดยคูณด้วย 12
สุดท้ายให้ทดลองเรียก `apply_workout_intensity` โดยส่งระยะเวลา 30 นาที พร้อมกับฟังก์ชัน `light_workout` ในครั้งแรก
และฟังก์ชัน `intense_workout` ในครั้งที่สอง แล้วพิมพ์ผลลัพธ์แต่ละครั้งออกทางหน้าจอ

**โจทย์ให้เขียนโค้ด**: จงเขียนฟังก์ชัน Python จากคำอธิบายขั้นตอนข้างต้นด้วยตนเอง แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 3 (คำอธิบายขั้นตอน)

**โจทย์**: ระบบบันทึกเกรดต้องการฟังก์ชันคำนวณเกรดเฉลี่ยแบบถ่วงน้ำหนัก (weighted average) จากรายวิชาที่นักศึกษาลงทะเบียน
โดยฟังก์ชันต้องเป็นฟังก์ชันบริสุทธิ์ (pure function) คือคำนวณแล้วคืนค่าออกไปเท่านั้น ห้ามแก้ไขข้อมูลเดิมหรือพิมพ์ค่าใด ๆ
ออกทางหน้าจอภายในฟังก์ชันเอง (ไม่มีผลข้างเคียง หรือ side effect)

**คำอธิบายขั้นตอน**: ให้เขียนฟังก์ชันชื่อ `calculate_weighted_average` ที่รับพารามิเตอร์หนึ่งตัวคือลิสต์ของข้อมูลรายวิชา
โดยแต่ละรายวิชาเก็บอยู่ใน dictionary ที่มีฟิลด์ `"score"` (คะแนนของวิชานั้น) กับ `"credit"` (หน่วยกิตของวิชานั้น)
ขั้นตอนการทำงานคือ วนอ่านแต่ละวิชาในลิสต์ แล้วคูณคะแนนของวิชานั้นด้วยหน่วยกิตของวิชานั้น สะสมผลคูณทั้งหมดไว้เป็น
"ผลรวมค่าถ่วงน้ำหนัก" และสะสมหน่วยกิตทั้งหมดไว้เป็น "ผลรวมหน่วยกิต" หลังวนครบทุกวิชาแล้ว ให้นำผลรวมค่าถ่วงน้ำหนัก
หารด้วยผลรวมหน่วยกิต เพื่อคำนวณเป็นเกรดเฉลี่ย แล้วคืนค่าเกรดเฉลี่ยนั้นกลับออกไปเพียงอย่างเดียว (ห้ามพิมพ์ค่าใด ๆ
หรือแก้ไขลิสต์ต้นฉบับภายในฟังก์ชัน) จากนั้นให้ทดลองเรียกฟังก์ชันนี้กับข้อมูลวิชาสามวิชา คือ
`{"score": 3.5, "credit": 3}`, `{"score": 4.0, "credit": 2}`, `{"score": 3.0, "credit": 1}` แล้วพิมพ์ผลลัพธ์ที่ได้
ออกทางหน้าจอ (การพิมพ์ทำที่นอกฟังก์ชัน ไม่ใช่ในฟังก์ชัน)

**โจทย์ให้เขียนโค้ด**: จงเขียนฟังก์ชัน Python จากคำอธิบายขั้นตอนข้างต้นด้วยตนเอง แล้วรันเพื่อตรวจคำตอบ (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์)

### ข้อที่ 4 (โจทย์/pain point เท่านั้น)

**โจทย์**: ระบบทำแบบทดสอบออนไลน์มีฟังก์ชันเดิมชื่อ `process_quiz_result` ที่ทำหลายอย่างปนกันไว้ในฟังก์ชันเดียว
ทั้งตรวจสอบว่าจำนวนข้อที่ตอบถูกที่กรอกมาอยู่ในช่วงที่เป็นไปได้หรือไม่ (ไม่เกินจำนวนข้อทั้งหมด) คำนวณเปอร์เซ็นต์ที่ทำได้
และพิมพ์ผลคะแนนออกทางหน้าจอ ทำให้ฟังก์ชันนี้แก้ไขยากและทดสอบยากทุกครั้งที่มีการเปลี่ยนรูปแบบการแสดงผลในอนาคต

ให้ออกแบบชุดฟังก์ชัน Python ใหม่ที่ยึดหลักความรับผิดชอบเดียว (Single Responsibility Principle) โดยแยกแต่ละหน้าที่

ฟังก์ชันเหล่านี้ทำงานร่วมกันได้อย่างไร โดยไม่มี pseudocode หรือขั้นตอนกำกับ ผู้เรียนต้องออกแบบชื่อฟังก์ชัน พารามิเตอร์
และการทำงานภายในเองทั้งหมด (คำเฉลยอยู่ในหมวด "เฉลย" ท้ายไฟล์ — เป็นเพียงหนึ่งในหลายวิธีออกแบบที่เป็นไปได้)

```python
03
04  def calculate_percentage(num_correct, total_questions):
05      return (num_correct / total_questions) * 100
06
07  def display_quiz_result(student_name, percentage):
08      print(student_name + ": ทำได้ " + str(percentage) + "%")
09
10  def process_quiz_result(student_name, num_correct, total_questions):
11      if not validate_num_correct(num_correct, total_questions):
12          print("ข้อมูลไม่ถูกต้อง: ตอบถูก " + str(num_correct) + " จาก " + str(total_questions) + " ข้อ")
13          return None
14      percentage = calculate_percentage(num_correct, total_questions)
15      display_quiz_result(student_name, percentage)
16      return percentage
17
18  process_quiz_result("มานี", 8, 10)
19  process_quiz_result("ชูใจ", 15, 10)
```

**Output:**
```
มานี: ทำได้ 80.0%
ข้อมูลไม่ถูกต้อง: ตอบถูก 15 จาก 10 ข้อ
```

หมายเหตุ (ขอบเขตนอกเหนือจากสไลด์): หลักความรับผิดชอบเดียว (Single Responsibility Principle) และแนวคิดลายเซ็นฟังก์ชัน/สัญญา
(function signature/contract) ไม่มีอยู่ใน `slides/06_function.md` — ดูรายละเอียดใน `lecture_note_advanced.md` หัวข้อที่ 14
และ 15 ตัวอย่างเฉลยนี้เป็นเพียงหนึ่งในหลายวิธีออกแบบที่เป็นไปได้ (pain point ไม่มีคำตอบตายตัวเพียงแบบเดียว) โดยแยกออกเป็น
4 ฟังก์ชันย่อยที่แต่ละฟังก์ชันรับผิดชอบหน้าที่เดียว (ตรวจสอบความถูกต้อง / คำนวณเปอร์เซ็นต์ / แสดงผล) แล้วให้ `process_quiz_result`
ทำหน้าที่เป็นฟังก์ชันประสาน (orchestrator) เรียกใช้ฟังก์ชันย่อยเหล่านั้นตามลำดับ ทุกฟังก์ชันในตัวอย่างนี้ยัง return
ค่าเดียวเสมอ (หรือไม่ return เลยในกรณีของ `display_quiz_result`) ไม่ขัดกับกฎของสไลด์ 6
